# Interview Preparation

This folder turns the course into interview readiness.

## Daily 60 Minute Drill

- 10 minutes: review one C++ concept.
- 30 minutes: solve one coding problem.
- 10 minutes: test and discuss edge cases.
- 10 minutes: explain complexity and production concerns.

## Weekly 3 Hour Mock

1. 45 minutes: coding problem.
2. 30 minutes: C++ deep dive.
3. 45 minutes: system design.
4. 30 minutes: behavioral question.
5. 30 minutes: retrospective and rewrite.

## C++ Flash Questions

Answer these out loud:

1. What is RAII?
2. Rule of zero vs rule of five?
3. Why does a polymorphic base class need a virtual destructor?
4. `unique_ptr` vs `shared_ptr`?
5. Reference vs pointer?
6. What is a dangling reference?
7. What is iterator invalidation?
8. What is undefined behavior?
9. What is move semantics?
10. When can `std::string_view` be dangerous?
11. Mutex vs atomic?
12. What is a data race?
13. Why use condition variable predicates?
14. What is false sharing?
15. How do you design exception-safe code?

## System Design Prompts

Practice these in 35 to 45 minutes:

1. URL shortener.
2. File storage service.
3. Chat system.
4. News feed.
5. Notification service.
6. Metrics pipeline.
7. Distributed rate limiter.
8. Feature flag service.
9. Search autocomplete.
10. Payment processing.

For each prompt, cover:

- Requirements.
- APIs.
- Scale estimates.
- Data model.
- Architecture.
- Bottlenecks.
- Failure modes.
- Observability.
- Tradeoffs.

## Behavioral Story Bank

Prepare stories for:

- A bug you fixed.
- A system you designed.
- A time you disagreed.
- A time you missed something.
- A time you improved quality.
- A time you learned quickly.
- A time you handled ambiguity.
- A time you made a tradeoff.

Use the STAR format, but keep it natural.

## Project Pitch Template

When explaining a project:

1. Problem: what was needed?
2. Constraints: what made it hard?
3. Design: what did you build?
4. Tradeoffs: what alternatives did you reject?
5. Correctness: how did you test it?
6. Performance: what did you measure?
7. Failure: what could go wrong?
8. Result: what changed?
